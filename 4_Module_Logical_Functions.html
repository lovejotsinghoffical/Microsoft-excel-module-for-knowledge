T25 IF()

The IF() function tests a condition and returns one value if it's TRUE, another if it's FALSE. It's the foundation every other logical function builds on.

=IF(logical_test, value_if_true, value_if_false)

Applied to the dataset — Attendance Status

In Salary_Data, column N (Attendance Status) is blank. Mark an employee "Present" if Days Present (column F) is 24 or more, otherwise "Irregular".

=IF(F2>=24,"Present","Irregular")

Fill this down from N2 to N31 (30 employees).

💡
Tip: IF() always returns exactly one of two outcomes. The moment you need a third outcome, you need nested IF — that's T26.

Try it yourself Easy

In a spare column, write a formula that marks "Senior" if Years of Experience (H) is 5 or more, else "Junior".

T26 Nested IF()

When there are more than two possible outcomes, IF() functions are nested inside each other. Excel evaluates top to bottom and stops at the first TRUE condition.

=IF(cond1, result1,
  IF(cond2, result2,
    IF(cond3, result3, result_default)))

Applied to the dataset — Bonus %

Column I (Bonus %) should assign a bonus percentage based on Performance Rating (column G):

RatingBonus %
510%
47%
34%
1–20%
=IF(G2=5,10%,
  IF(G2=4,7%,
    IF(G2=3,4%,0%)))
⚠️
Common mistake: forgetting a closing bracket for each nested IF. 3 nested IFs need 3 closing ) at the end — count them before pressing Enter.

Cleaner alternative — IFS()

If your Excel version supports it (365 / 2019+), IFS() avoids the bracket-counting problem entirely:

=IFS(G2=5,10%, G2=4,7%, G2=3,4%, TRUE,0%)

Try it yourself Medium

Compute Bonus Amount in column J as Basic Salary × Bonus %, then Gross Salary in column K as Basic Salary + Bonus Amount.

T27 AND(), OR(), NOT()

These combine multiple conditions into a single TRUE/FALSE, which then feeds into IF().

AND()

TRUE only if every condition is TRUE.

=AND(cond1, cond2, ...)

OR()

TRUE if at least one condition is TRUE.

=OR(cond1, cond2, ...)

NOT()

Reverses a TRUE/FALSE result.

=NOT(condition)

Applied to the dataset — Increment Eligible

Column L (Increment Eligible): mark "YES" if (Rating ≥ 4 AND Days Present ≥ 24) OR Years of Experience ≥ 10.

=IF(OR(AND(G2>=4,F2>=24), H2>=10),
   "YES","NO")

A NOT() example — flag anyone who is not a Sales employee:

=IF(NOT(C2="Sales"),"Non-Sales","Sales")
📝
Remember: AND/OR/NOT return TRUE or FALSE on their own — they only become "IF X do this" logic once wrapped inside an IF().

Try it yourself Medium

Flag employees "At Risk" if Days Present < 20 AND Rating <= 2.

T28 SUMIF() & COUNTIF()

These aggregate data based on a condition — the bridge between logical tests and summary reporting.

=SUMIF(range, criteria, sum_range)
=COUNTIF(range, criteria)

Applied to the dataset — Department Summary

Below row 31 in Salary_Data, build a small summary table:

// Total Basic Salary for Sales department
=SUMIF(C2:C31,"Sales",D2:D31)

// Number of employees in IT
=COUNTIF(C2:C31,"IT")

Repeat for each department: Sales, IT, HR, Finance, Marketing.

DepartmentFormula (Total Salary)Formula (Headcount)
Sales=SUMIF(C:C,"Sales",D:D)=COUNTIF(C:C,"Sales")
IT=SUMIF(C:C,"IT",D:D)=COUNTIF(C:C,"IT")
HR=SUMIF(C:C,"HR",D:D)=COUNTIF(C:C,"HR")

Bonus: SUMIFS / COUNTIFS (multiple conditions)

Total Basic Salary for employees who are in Sales and have Rating ≥ 4:

=SUMIFS(D2:D31, C2:C31,"Sales", G2:G31,">=4")
💡
Tip: Criteria with comparison operators must be text strings: ">=24", not >=24.

Try it yourself Easy

Count how many employees have Days Present < 20 across the whole company (attendance concern count).

T29 IFERROR()

IFERROR() catches any error a formula produces (#N/A, #DIV/0!, #VALUE!, etc.) and replaces it with something meaningful.

=IFERROR(value, value_if_error)

Applied to the dataset — Grade lookup

Column M (Grade): use VLOOKUP against Lookup_Grade to convert Performance Rating into a Grade:

=IFERROR(
  VLOOKUP(G2, Lookup_Grade!A:B, 2, FALSE),
  "Check Rating"
)

Where this dataset makes IFERROR() essential

Try a VLOOKUP of DeptCode (column D) against Dept_Codes to pull the Full Department Name:

=IFERROR(
  VLOOKUP(D2, Dept_Codes!A:B, 2, FALSE),
  "Code Not Found"
)

Rows 7 and 19 have deliberately mismatched DeptCodes that don't exist in Dept_Codes — without IFERROR() these would show #N/A. With it, they'll clearly display "Code Not Found" instead, which is exactly what happens in real payroll sheets with data-entry typos.

⚠️
Don't overuse IFERROR: wrapping every formula in IFERROR() can hide genuine mistakes (like a wrong cell reference). Use it to handle expected exceptions — like missing lookup matches — not to silence bugs.

Try it yourself Hard

Pull HRA % from Dept_Codes for every employee, wrapped in IFERROR with fallback text "No HRA Data".
